# BikeNav Málaga — Technical Specification v1.2

A browser-only, client-side bike-lane navigation web app for Málaga, hosted on GitHub Pages. All Málaga data (basemap, routing graph, address search) is **pre-built offline and shipped as static artifacts**. There are **no runtime network or API dependencies** — no Google, no Photon, no Nominatim, no CartoCiudad REST, no Overpass at runtime.

> **Changes in v1.2:** added the deployment & CI/CD section (§17) — GitHub Pages in **branch mode** (`gh-pages`), a production deploy workflow, and a **PR preview** workflow that publishes each pull request to an isolated preview URL and cleans it up on close. Directory structure, tech stack and open questions updated; subsequent sections renumbered.
> 
> **Changes in v1.1:** added live speed measurement, start/stop journey sessions (§12), local journey history (§13), and a personalized ETA model that uses the rider’s own historical average speed (§14). The displayed ETA is now separated from the routing cost. Goals, non-goals, map/UI, tech stack, milestones and open questions updated accordingly.

-----

## 1. Goals

1. Find the **fastest cycling route** between two points over Málaga’s bike-lane + road network.
1. **Prefer bike infrastructure** but transparently connect through roads when needed (e.g. linking two parallel bike lanes via the road between them).
1. A user-adjustable **preference slider** (“stay on bike lanes” ↔ “faster even on roads”), modeled on Valhalla’s `use_roads` 0–1 dial.
1. **Hard-exclude** motorways and any segment where cycling is prohibited.
1. **Address/place search** entirely client-side against official Málaga data — no geocoding API.
1. Let users **import their own GeoJSON** line data and route over it.
1. **Measure live speed and ride progress** during navigation, controlled by **start/stop** of a journey session.
1. **Save a history of completed journeys** locally on the device (never uploaded).
1. Compute the **estimated time from the rider’s own historical average speed** when enough history exists, defaulting to per-class priors until then.

## 2. Non-goals (v1)

- No turn-by-turn **voice** guidance. (Live position/speed tracking and a navigation HUD **are** in scope — see §12 — but without spoken instructions.)
- No multi-modal (bus/train) routing.
- No live traffic, elevation, or surface-quality costing.
- No backend, database, login, account, or cloud sync of any kind. (Journey history is local-only IndexedDB.)
- No nationwide coverage — Málaga municipality only (imports excepted).

## 3. Hard constraints

|Constraint                             |Implication                                                                                                                                                                                                                                                                                                                     |
|---------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|GitHub Pages static hosting            |No server code; everything is static files + client JS. Site ≤ 1 GB, individual files ≤ 100 MiB.                                                                                                                                                                                                                                |

## 5. Data sources (build-time only)

All consumed **only by the offline pipeline**. None is fetched at runtime.

|Layer                     |Source                                                                       |Format / CRS      |License                  |
|--------------------------|-----------------------------------------------------------------------------|------------------|-------------------------|
|Bike lanes (authoritative)|Málaga portal: `carriles-bici`                                               |GeoJSON, EPSG:4326|CC BY 4.0                |
|Road network              |OSM via Overpass (highway + access tags) — needed for cycling permissions    |OSM → GeoJSON     |ODbL                     |
|House-number points       |Málaga portal: SIC `Número` (`da_cartografiaNumero-4326.geojson`)            |GeoJSON, EPSG:4326|CC BY 4.0                |
|Street names              |Málaga portal: SIC `Vial` (join on `CODVIAL`) + `Abreviatura tipos de viales`|CSV               |CC BY 4.0                |
|Basemap                   |OSM-derived vector tiles (Planetiler/Protomaps), Málaga extract              |PMTiles           |ODbL (data) / BSD (style)|

**Why OSM for roads:** the routing graph needs cycling-permission tags (`bicycle=no`, `highway=motorway`/`motorway_link`, `access=no`) to satisfy the hard-exclusion requirement. The municipal road layer lacks these. Bike infrastructure is taken from the municipal `carriles-bici` layer, augmented with OSM `highway=cycleway`.

**Licensing note:** because the prebuilt graph/basemap derive from OSM (ODbL), the app must display “© OpenStreetMap contributors” and “© Ayuntamiento de Málaga”; ODbL share-alike applies to the derived graph database. Acceptable for a community app.

## 6. Offline build pipeline

Deterministic, re-runnable, version-pinned. Output = the static artifacts in §8. Implemented as `npm run build:data` orchestrating these stages:

**Stage 1 — Acquire & normalize.**

- Download municipal GeoJSON (already EPSG:4326). Download OSM roads for the Málaga bbox (Overpass query, build-time only).
- Reproject anything not already WGS84:
  `ogr2ogr -f GeoJSON -t_srs EPSG:4326 -s_srs EPSG:25830 out.geojson in.geojson`
- Round coordinates to 6 decimals to shrink files.

**Stage 2 — Build the routing network (the core).**

1. Merge bike-lane lines + road lines into one LineString FeatureCollection.
1. Tag each feature with `cls` (edge class, §7.2) and `oneway` from source attributes / OSM tags.
1. **Node the topology** so crossing/touching lines share exact vertices: `turf.lineSplit` at every intersection.
1. **Snap dangling endpoints** to the nearest network node within tolerance (configurable, default 12 m) — this is what connects parallel bike lanes through the road between them. Use a node-snap pass over an rbush/flatbush spatial index.
1. **Drop excluded edges** (motorway, motorway_link, `bicycle=no`, `access=no`) entirely.
1. Compute each edge’s geodesic `len` in metres.
1. Assign integer node ids; emit nodes array + edges array.
1. **Validate**: report connected-component count; warn if the largest component covers < 98% of bike-lane length (indicates snapping gaps).

**Stage 3 — Serialize the graph** to `/data/graph.bin` (§7.1).

**Stage 4 — Build the address index.**

1. Join `Número` → `Vial` on `CODVIAL`; attach `NOMVIAL`; expand `CODTIPVIAL` to a type prefix (“Calle”, “Avenida”, …); compose `display` (“Calle Larios 5”).
1. Filter `TIPNUMERO` ∈ {P, A}; drop rows with non-empty `FECBAJA`.
1. Build a **FlexSearch Document index** over `{id, display, street, number, postcode}`; **export** it to static files (`/data/search/index.*`).
1. Emit `coords.bin`: a packed array indexed by `id` → `[lon, lat]` (Float32, §9.3).
1. Emit `search/meta.json` (record count, field schema, attribution).

**Stage 5 — Build display tiles.**

- Basemap: Planetiler/Protomaps → `basemap.pmtiles` (Málaga extract, ≤ 100 MiB).
- Bike lanes: `tippecanoe` → `bikelanes.pmtiles` for styled rendering.

**Stage 6 — Emit `manifest.json`** with artifact versions, SHA-256 checksums, data bbox, build date, and attribution strings. The app reads this first and verifies checksums before loading.

## 7. Routing engine spec

### 7.1 Prebuilt graph format (`graph.bin`)

Binary little-endian for compact load (a JSON variant `graph.json` may be used in early milestones):

```
Header:  magic "BNG1" | version u16 | nodeCount u32 | edgeCount u32 | bbox 4×f32
Nodes:   nodeCount × [lon f32, lat f32]                     // index = node id
Edges:   edgeCount × [a u32, b u32, len f32, cls u8, one i8] // one: 0 both, 1 a→b, -1 b→a
```

At load, `routing.worker` parses this into an `ngraph.graph`: one directed link per allowed direction, with edge payload `{len, cls}`.

### 7.2 Edge classes & base (prior) speeds

Speeds here are **cold-start priors**, used for ETA until personal history is available (§14), and they set the relative ordering between surface types. `time = len / speed(cls)`.

|`cls`          |Meaning                           |Prior speed (km/h)|
|---------------|----------------------------------|------------------|
|`cycleway`     |Segregated cycle track            |18                |
|`cycle_lane`   |On-road painted lane              |16                |
|`cycle_street` |Bike-priority street              |16                |
|`path`         |Shared path (bikes allowed)       |13                |
|`living_street`|Calmed street                     |14                |
|`residential`  |Residential road                  |15                |
|`tertiary`     |Minor through-road                |16                |
|`secondary`    |Secondary road                    |16                |
|`primary`      |Major road (bikes allowed)        |16                |
|`link`         |On/off ramps (bikes allowed)      |14                |
|`connector`    |Synthetic snap link between layers|10                |

Excluded at build time (never in the graph): `motorway`, `motorway_link`, anything `bicycle=no`/`access=no`.

### 7.3 Preference model (the slider)

Single control `p ∈ [0,1]` (UI: “Prefer bike lanes” 0 ↔ “Fastest” 1). A per-class **comfort penalty** multiplies time to form the **routing cost** (path selection only — not the ETA):

```
isBike(cls)  = cls ∈ {cycleway, cycle_lane, cycle_street, path}
penaltyMax   = 4.0                       // tunable
roadPenalty  = 1 + (1 - p) * (penaltyMax - 1)
penalty(cls) = isBike(cls) ? 1.0
             : cls === 'connector' ? (1 + (1 - p) * 2.0)
             : roadPenalty
routingCost(edge) = (edge.len / priorSpeed(edge.cls)) * penalty(edge.cls)
```

- `p = 0`: roads cost ~4× → routes hug bike lanes, using roads only to bridge gaps.
- `p = 1`: penalties collapse to 1 → fastest-time routing regardless of surface.
- Default `p = 0.35`.

The penalty is applied **live** inside `ngraph.path`’s distance function, so moving the slider re-routes without rebuilding the graph. **The comfort penalty never affects the displayed ETA** — see §14.

### 7.4 Algorithm

- `ngraph.path` **NBA*** (bidirectional A*, optimal & fastest) with a time-based heuristic (great-circle distance / max speed) admissible for the routing cost.
- Exclusions enforced both at build time (edges absent) and via a `blocked()` guard as defence-in-depth.

### 7.5 Endpoint snapping

User start/end points are snapped before search:

1. rbush/flatbush nearest-edge query.
1. `turf.nearestPointOnLine` → snap point + host edge.
1. Insert a **temporary node** splitting that edge into two temp edges (preserving `cls`); remove after the query.

This lets routes start/end mid-segment, not only at graph vertices. The same snap-onto-route primitive is reused for live progress tracking (§12.3).

### 7.6 Output

`routing.worker` returns:

```
{
  geometry: GeoJSON LineString,
  distance_m,
  eta_s,                 // personalized realistic time (§14), NOT routing cost
  etaSource: 'personal-perclass' | 'personal-overall' | 'prior',
  steps: [...],
  classBreakdown: { cls: distance_m },   // distance per edge class
  usedRoadShare: 0–1                     // fraction of distance on non-bike edges
}
```

`usedRoadShare` lets users see the bike-vs-road trade-off of the current slider value; `etaSource` tells the UI whether the estimate is personalized yet.

## 9. Address search spec

### 9.1 Index

Prebuilt FlexSearch **Document** index (exported at build time, never rebuilt at runtime). Loaded into `search.worker`. Fields: `display`, `street` (boosted), `number`, `postcode`. Tokenizer: forward (prefix) for autocomplete; accent-folding for Spanish (á→a, ñ handled explicitly).

### 9.2 Query flow

Debounced (120 ms) keystrokes → `search.worker.query(text, {limit: 8})` → ranked candidates → on select, read `coords.bin[id]` → `map.flyTo` + marker, and offer “route from here / to here”.

### 9.3 Coordinate store (`coords.bin`)

`Float32Array`, two floats per record, indexed by contiguous `id`. O(1) lookup, no parsing. Header: `magic "BNC1" | count u32`.

### 9.4 Degradation (within the no-fallback rule)

If first-load payload or mobile memory is exceeded, the **build pipeline** switches to a street-level index (a few thousand entries) plus per-street number lists loaded on selection — still 100% prebuilt static files, still no API. This is a build-time configuration switch, not a runtime fallback.

## 10. Map & UI spec

- **MapLibre GL JS**, basemap via `pmtiles://` (`addProtocol`). No tile-server key.
- Layers: basemap → bike-lanes (PMTiles, styled) → route line → progress overlay → start/end/search/position markers.
- Core controls: search box (autocomplete), start/end pickers (search result, map click, or “my location” via the browser Geolocation API only — not a network service), **preference slider** `p`, “import GeoJSON” button, attribution control (fixed: © OpenStreetMap, © Ayuntamiento de Málaga).
- **Route panel** (pre-ride): distance, **ETA** (personalized when available, §14), `usedRoadShare`, and a textual step list, plus a **Start** button.
- **Navigation HUD** (during ride, §12): large current speed, average moving speed, elapsed time, distance covered, remaining distance, dynamic ETA, recenter button, wake-lock indicator, and **Pause / Stop** buttons. An **off-route banner** offers reroute.
- **History panel** (§13): list of past journeys (date, labels, distance, time, avg speed); tap to view a journey’s track + stats on the map; per-journey delete; clear-all; export/import JSON.
- Permission prompts: clear copy before requesting Geolocation and Screen Wake Lock; the app works without them (planning/search only), but live navigation requires Geolocation.

## 11. User GeoJSON import

The one place graph-building happens at runtime — but it is the **same deterministic pipeline** as the offline build, run in `import.worker`, producing an in-memory prebuilt index (consistent with “only prebuilt indexes”):

1. Validate input is a FeatureCollection of LineStrings (reject otherwise with a clear message).
1. Run clean → node (`turf.lineSplit`) → snap (configurable tolerance, default 12 m) → class-tag (user may map properties to `cls`, else default `path`) → build temp `ngraph.graph`.
1. Either route purely on the imported network, or **merge** with the Málaga graph (snapping imported endpoints to Málaga nodes within tolerance).
1. Report connected-component count and warn on disconnected geometry.

No imported data is uploaded anywhere; it stays in the browser session.

## 12. Live speed & journey sessions

### 12.1 Speed source & calculation

- Position via the **Geolocation API** `watchPosition({ enableHighAccuracy: true, maximumAge: 1000 })`. Each fix carries `lat, lon, accuracy, timestamp` and optionally `speed` (m/s) and `heading`.
- **Effective speed per fix:**
  - If `fix.speed != null` and `fix.accuracy ≤ ACC_MAX` → use `fix.speed`.
  - Else **derive**: `haversine(prev, cur) / dt`, when `dt` is within bounds.
- **Filtering & smoothing:**
  - Reject fixes with `accuracy > ACC_MAX` (default 30 m).
  - Reject speeds `> BIKE_MAX` (default 60 km/h) as GPS glitches.
  - Smooth the displayed current speed with an EMA (α ≈ 0.3).
  - **Stopped detection:** speed `< STOP_THRESH` (default 1.0 km/h) marks a stopped interval; *moving time* excludes stops so personal average speed reflects actual riding pace.
- **Live metrics** maintained per ride: `currentSpeed` (smoothed), `avgMovingSpeed = movingDistance / movingTime`, `maxSpeed`, `distanceCovered`, `elapsedTime`, `movingTime`, `remainingDistance`, `dynamicETA` (§14.3).

### 12.2 Session lifecycle (start/stop)

States: `IDLE → ROUTED → ACTIVE → (PAUSED) → FINISHING → SAVED | DISCARDED`.

- **Start** (requires a computed route, or *free-track* mode with no route): acquire **Screen Wake Lock** to keep the screen on, begin `watchPosition`, start timers, begin recording a downsampled track.
- **Pause / Resume**: stop accumulating time/track without ending the session.
- **Stop (Finish)**: finalize stats, write a journey record (§13), update the speed profile (§14), release wake lock, clear the watch.
- **Cancel**: discard the session without saving.

### 12.3 Progress & off-route handling (ROUTED mode)

- Project the current position onto the route line (`turf.nearestPointOnLine`) → distance-along-route and `remainingDistance`.
- **Off-route**: if perpendicular distance to the route `> OFFROUTE` (default 35 m) for `> OFFROUTE_T` seconds, show the reroute banner; on accept, recompute from the current position to the destination with the same `p`.

### 12.4 Free-track mode

Start without a planned route to simply record a ride (no ETA, no off-route logic). Still saved to history and still feeds the personal speed profile.

### 12.5 Privacy

Position, track, and speed never leave the device. Geolocation and Wake Lock require explicit user permission. The app degrades gracefully to planning/search when permission is denied.

## 13. Journey history & storage

### 13.1 Engine

**IndexedDB** via the `idb` wrapper (localStorage is too small for tracks). DB `bikenav`, version 1. All local; no sync, no upload.

### 13.2 Object stores

**`journeys`** (keyPath `id`):

```
id, createdAt, startedAt, endedAt,
mode: 'routed' | 'free',
startLabel, endLabel, startCoord, endCoord,
preferenceP,                      // slider value used
plannedDistance_m, plannedEta_s,  // estimate at start (routed mode)
actualDistance_m, elapsedTime_s, movingTime_s,
avgMovingSpeed_kmh, maxSpeed_kmh,
classBreakdown: { cls: { distance_m, movingTime_s } },
track: simplifiedPolyline,        // turf.simplify, tol ~5 m, point-capped
routeGeometry: LineString | null  // planned route (routed mode)
```

**`speedProfile`** (single record, key `'default'`): aggregate derived stats, maintained incrementally on each save so ETA never rescans all journeys:

```
overall:  { avgSpeed_kmh, totalDistance_m, totalMovingTime_s, sampleJourneys },
perClass: { cls: { avgSpeed_kmh, distance_m, movingTime_s, sampleCount } },
updatedAt
```

**`meta`**: schema version, settings (units, thresholds, retention).

### 13.3 Per-class attribution

To populate `classBreakdown` without heavy GPS map-matching, **routed** journeys attribute each completed segment of the planned route to its edge class, proportioned by the rider’s progress; *free* journeys attribute all distance to a generic class (or to nearest-edge class if a light snap is enabled). v1 may start with route-based attribution; raw-GPS map-matching is an optional later refinement (see open questions).

### 13.4 Retention & export

- Cap stored **tracks** to the last `N_TRACKS` journeys (default 200); older journeys keep stats only.
- Show storage used; provide **delete one**, **clear all**, and **export/import history as JSON** (the user owns their data).

## 14. Personalized ETA model

Two clearly separated quantities (v1.0 conflated them):

- **Routing cost** (path selection, §7.3): `time × comfort penalty(p)`. Internal only; never shown.
- **Displayed ETA** (realistic time): `Σ over route edges ( len / effectiveSpeed(cls) )` — **no comfort penalty**.

### 14.1 Effective speed per class

```
s = priorSpeed(cls)                                   // §7.2 cold-start prior
if profile.perClass[cls].sampleCount ≥ N_CLS:         // confident per-class
    s = profile.perClass[cls].avgSpeed_kmh
    etaSource = 'personal-perclass'
else if profile.overall.sampleJourneys ≥ N_OVR:       // confident overall only
    s = priorSpeed(cls) * (profile.overall.avgSpeed_kmh / priorOverallMean)
    etaSource = 'personal-overall'                    // scale priors to the rider's pace,
                                                      // preserving cycleway>road ordering
else:
    etaSource = 'prior'
```

- `N_CLS` default: ≥ 3 journeys touching that class **or** ≥ 2 km accumulated on it.
- `N_OVR` default: ≥ 3 completed journeys.
- Profile averages use a distance-weighted EMA over recent journeys so the estimate adapts as the rider changes.
- **Cold start (no history): pure priors.** This is an initial prior, not a runtime external fallback, so it is consistent with the no-fallback rule (§3).

### 14.2 Pre-ride ETA

Computed in `routing.worker` from the chosen route’s per-edge classes and `effectiveSpeed(cls)`; returned as `eta_s` with `etaSource` (§7.6).

### 14.3 Dynamic ETA during a ride

```
currentEffectiveSpeed = blend( liveAvgMovingSpeed, profileSpeed )
liveWeight            = min(0.8, movingTime_s / 600)      // trust the live ride more over time
remainingETA          = remainingDistance / currentEffectiveSpeed
```

Recomputed on each accepted fix, throttled to ≤ 1 Hz, and shown in the HUD.

## 17. Deployment & CI/CD

The site is published to **GitHub Pages in branch mode** and built/deployed entirely by GitHub Actions. Two workflows: production deploy on merge to `main`, and per-PR preview deploys with automatic cleanup.

### 17.1 Pages configuration (one-time)

- Repo **Settings → Pages → Build and deployment → Source: “Deploy from a branch”**, **Branch: `gh-pages`**, **Folder: `/ (root)`**.
- The `gh-pages` branch is created automatically by the first workflow run; it holds the published site plus a `pr-preview/` umbrella directory for preview builds.
- Project-page URL: `https://<user>.github.io/<repo>/`. PR previews live at `https://<user>.github.io/<repo>/pr-preview/pr-<N>/`.

### 17.2 What CI builds (and does not)

- CI runs **`build:app` only** (Vite bundle). The heavy `build:data` pipeline (GDAL, tippecanoe, Overpass) is run **locally by a maintainer**, and the resulting `/data/*` artifacts are **committed to the repo**. This keeps CI fast, deterministic, and free of build-time network calls — consistent with the prebuilt-index philosophy.
- Regenerating data is therefore a deliberate maintainer action (PR that updates `/data/*`), not something CI does on every push.

### 17.3 Workflows

**`.github/workflows/deploy.yml` — production (push to `main`):**

```yaml
name: Deploy
on:
  push:
    branches: [main]
permissions:
  contents: write
concurrency:
  group: pages-production
  cancel-in-progress: false
jobs:
  build-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run build:app          # data artifacts already committed
      - name: Publish to gh-pages root
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
          keep_files: true              # preserve pr-preview/ subdirectories
```

**`.github/workflows/preview.yml` — PR preview + cleanup (`pull_request` opened / reopened / synchronize / closed):**

```yaml
name: PR Preview
on:
  pull_request:
    types: [opened, reopened, synchronize, closed]
permissions:
  contents: write          # push preview to gh-pages
  pull-requests: write     # post the preview-URL comment
concurrency:
  group: preview-${{ github.event.number }}
  cancel-in-progress: true
jobs:
  preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        if: github.event.action != 'closed'
        with:
          node-version: 20
          cache: npm
      - run: npm ci
        if: github.event.action != 'closed'
      - run: npm run build:app
        if: github.event.action != 'closed'
      - name: Deploy / remove preview
        uses: rossjrw/pr-preview-action@v1
        with:
          source-dir: ./dist
          preview-branch: gh-pages
          umbrella-dir: pr-preview
          action: auto       # deploy on open/sync, remove on close
```

On open/update this publishes `dist/` to `gh-pages:/pr-preview/pr-<N>/` and comments the preview URL on the PR; on close it deletes that subdirectory. Production deploys use `keep_files: true` so they never wipe live previews, and previews are isolated under `pr-preview/` so they never touch the production site.

### 17.4 Relative-base requirement

Because previews are served from a deep subpath (`/<repo>/pr-preview/pr-<N>/`), all asset and data URLs **must be relative**. Set Vite `base: './'` and fetch artifacts as `./data/...` (not `/data/...`). This single setting makes the same `dist/` bundle work at the production path and at every preview subpath without per-build rewriting.

### 17.5 Large artifacts & Git LFS caveat

`/data/*` (notably `basemap.pmtiles`, up to 100 MiB) are committed as **regular Git files**, never Git LFS: **GitHub Pages does not serve Git-LFS objects**, so an LFS-tracked artifact would 404 at runtime. Keep each artifact under the 100 MiB hard file limit and the site under the 1 GB Pages limit; if the basemap approaches the limit, shrink the extract bbox (§19.6) rather than reaching for LFS.

### 17.6 Acceptance

- Merging to `main` republishes the production site within one workflow run; the network audit (§18 / M7) still shows only same-origin `/data` requests.
- Opening a PR posts a working preview link; pushing new commits updates it; closing the PR removes the preview directory and the production site is unaffected.

## 18. Performance budgets

|Metric                                       |Target          |Hard ceiling|
|---------------------------------------------|----------------|------------|
|First contentful map                         |< 2 s           |4 s         |
|Routing graph parse (worker)                 |< 400 ms        |1 s         |
|Search index ready (worker)                  |< 600 ms        |1.5 s       |
|Single route (NBA*)                          |< 150 ms        |500 ms      |
|Autocomplete keystroke→results               |< 80 ms         |150 ms      |
|Geolocation fix handling (speed/progress/ETA)|< 10 ms         |30 ms       |
|Dynamic ETA recompute                        |throttled ≤ 1 Hz|—           |
|Journey save to IndexedDB                    |< 50 ms (async) |200 ms      |
|Total first-load transfer (gz)               |< 25 MB         |40 MB       |

Breaching a load ceiling triggers the build-time degradation switches (street-level search index; graph tiling).

## 19. Milestones & acceptance criteria

**M1 — Map shell.** MapLibre + basemap PMTiles + bike-lanes layer render on Pages. *Accept:* map loads with zero network calls beyond static `/data`.

**M2 — Bike-only routing.** Prebuilt graph from `carriles-bici` only; NBA* routing in worker; endpoint snapping. *Accept:* route within connected bike network returns < 1 s.

**M3 — Fused graph + exclusions.** Add OSM roads; node/snap pipeline; motorway/`bicycle=no` excluded. *Accept:* a route between two disconnected parallel bike lanes correctly traverses the connecting road; no route ever uses a motorway.

**M4 — Preference slider.** Live `p` re-routing; `usedRoadShare` shown. *Accept:* `p=0` and `p=1` produce visibly different routes on a test pair; slider re-routes < 300 ms.

**M5 — Address search.** Prebuilt FlexSearch index + `coords.bin`; autocomplete; set start/end from results. *Accept:* searching a known Málaga address centres the map within budget, fully offline.

**M6 — Import.** User GeoJSON import → clean/node/snap → route. *Accept:* a sample imported network routes and merges with Málaga data; disconnected geometry is warned.

**M7 — Self-hosted basemap + polish.** Replace any keyed tiles with self-hosted PMTiles; attribution finalized. *Accept:* no API keys anywhere; site passes the no-runtime-dependency audit (network tab shows only same-origin `/data` requests).

**M8 — Live navigation, history & personalized ETA.** Start/stop journey sessions; live speed/HUD; IndexedDB history; speed profile; ETA from personal average. *Accept, all of:*

- (a) Starting a route shows live current/average speed, elapsed and remaining distance, and a dynamic ETA that updates while riding.
- (b) Stopping saves a journey that persists across a page reload and appears in the history panel with correct distance/time/avg-speed.
- (c) After ≥ `N_OVR` saved journeys, a newly planned route’s pre-ride ETA reflects the rider’s recorded average speed (`etaSource` ≠ `'prior'`), and differs from the cold-start estimate.
- (d) Off-route detection offers a reroute; export/import of history round-trips correctly.

## 20. Open questions (to resolve before/at M2–M8)

1. **Snap tolerance** (default 12 m) — validate against real lane/road geometry; expose as a build parameter.
1. **`penaltyMax`** (default 4) and per-class priors — tune empirically on sample routes.
1. **Número record count & file size** — confirm by downloading and counting; decides whether full portal-level search fits the budget or M5 uses the street-level switch.
1. **One-way handling for cycle infra** — confirm municipal/OSM oneway tagging quality for bidirectional cycle tracks.
1. **Connector-edge penalty** — tune so the router bridges layers willingly but doesn’t zig-zag between lane and road.
1. **Basemap extract bounds** — exact bbox to keep `basemap.pmtiles` under 100 MiB while covering the metropolitan cycling area.
1. **Speed thresholds** — `ACC_MAX` (30 m), `BIKE_MAX` (60 km/h), `STOP_THRESH` (1.0 km/h); validate on real rides and choose whether to trust native `fix.speed` vs derived speed.
1. **Personalization confidence** — `N_CLS`, `N_OVR`, and EMA vs last-K window; decide global-vs-per-class personalization granularity.
1. **Per-class attribution** — start with route-based attribution (§13.3) or invest in light GPS-to-graph map-matching for free-track rides?
1. **History retention** — `N_TRACKS` cap (default 200) and track simplification tolerance vs storage budget.
1. **Data artifact strategy in CI** — confirmed approach is committed `/data/*` + app-only CI (§17.2); revisit if artifacts grow enough to bloat clones (options: periodic scheduled rebuild workflow, or a separate data release asset fetched at build time).
